Install & release

One-line installers for macOS, Linux and Windows, what jevcli install writes where, building from source, and how releases are cut.

One line#

install.sh (macOS / Linux, POSIX sh) and install.cmd (Windows) do the same four things: pick the asset for your OS and CPU (jevcli_darwin_arm64, jevcli_linux_amd64, jevcli_windows_arm64.exe, …), download it from the latest GitHub release, put it on your PATH, and run jevcli install.

variableeffect
JEVCLI_VERSION=v0.9.0pin a release instead of latest
JEVCLI_BIN=DIRinstall the binary there (default ~/.local/bin; Windows %LOCALAPPDATA%\Programs\jevcli)
JEVCLI_NO_HOOK=1skills only, no Claude Code hook template

If a direct download fails and gh is installed, the script falls back to gh release download (useful while a repo is private). The script tells you if the directory is not on your PATH.

What jevcli install does#

  • --skills: write SKILL.md into ~/.claude/skills/jevcli, ~/.agents/skills/jevcli, and ~/.codex/skills/jevcli if ~/.codex exists.
  • --hooks: add one entry per plugin event to Claude Code's settings.json, each calling jevcli hook run EVENT. The plugins stay disabled, so the entries are no-ops until plugin enable.
  • Neither flag: both. Re-running is idempotent. jevcli uninstall with the same flags removes exactly what was written and leaves other skills and hooks alone.

From source#

Releases#

Pushing a v* tag runs .github/workflows/release.yml, which cross-compiles with CGO_ENABLED=0 for darwin, linux and windows on amd64 and arm64, stamps the tag into jevcli version, and attaches the six binaries to a GitHub release. The installers download from releases/latest by default.

This site is the docs/ folder, deployed by pages.yml on every push to main that touches docs/, the installers or the skill. That workflow also copies install.sh, install.cmd and SKILL.md (as skill.md) into the site root, which is why the install URLs above resolve.
