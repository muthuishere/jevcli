An agent skill for Claude Code, Codex and any agent

Typed judgements for coding agents.

jevcli lets an agent hand small decisions (is this urgent, which team, is this line an error) to a Jev-style decision model and get back a verdict with a probability, not prose. The agent keeps its own reasoning for the real work. Any System One endpoint works: hosted Jev, self-hosted, or a personal model.

Four ideas#

One command

jevcli ask takes any number of questions (yes/no, pick-one, rating) and one input or a batch. is, pick, filter and rank are the same command with the question already shaped.

Your questions, saved

jevcli question add urgent --noul "…" once, then jevcli ask urgent from any repo. --local keeps a question in the repo's .jevcli/questions.json, committed with the code.

Context from your agent files

It reads the ## Jev section of the AGENTS.md / CLAUDE.md you already have, global and per folder, and never writes them. jevcli context shows exactly what is sent.

Plugins as config

A Claude Code hook is a few JSON fields: an event, the questions to ask, and a condition to deny, warn, block or add context. Shipped disabled; shadow mode first.

What it is not#

  • Not a safety gate. Permissions, money, legal and irreversible actions stay with you. A plugin can deny a shell command, but it is a probability threshold, not a policy engine.
  • Not a generator. It never writes code, replies or files. A wrong answer is a wrong number, not a wrong patch.
  • Not local by default. The question text and the input go to whichever endpoint your profile points at. Point it at your own server if that matters; the ledger stores no content either way. See Reliability & privacy.
  • Not free. A hosted endpoint bills per call. jevcli stats shows calls and tokens per day so you can see it.
  • Not an explanation. You get yes 0.93, not why. Write the question so the number means something.
  • Not calibrated for you yet. The 0.8 / 0.2 thresholds are defaults. Check a few verdicts against your own judgement before trusting them in a loop, and tune per question (--yes, --no, --min).
