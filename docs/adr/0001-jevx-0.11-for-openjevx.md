# ADR 0001: jevx 0.11 — what openjevx should do about it

Status: proposed, for the openjevx maintainers to take up. Nothing in the openjevx repo was changed for this ADR.
Date: 2026-09-29

## Context

openjevx's recipes (`recipes/*.md`, served on `/recipes`) lean on `jq` twice: to build a request per input
(`jq -nc --arg l "$l" '{state: ...}' | curl ...`) and to pick fields out of `jevx ask` JSONL. Users who do not know jq
cannot read or adapt them. jevx v0.11.0 removes the need:

1. **A batch prints a readable table by default**, one row per input in input order: `VERDICT  P  INPUT` (a
   VERDICT/P pair per question when several are asked). `--raw` prints the full JSONL as before. This is a breaking
   change for anything that parsed the old default output; add `--raw` there.
2. **An answer cache, on by default.** One file per answer under `~/.cache/jevx/` (`cache_dir` in config.json), named
   by a SHA-256 of endpoint URL + model name + input + question. Only the model's answer and a timestamp are stored,
   never the input. Answers expire after `cache_ttl_days` (7). `--fresh` asks again and refreshes; `jevx cache
   enable|disable|ttl DAYS|dir PATH|clear|stat` manage it.

## Decision (recommended for openjevx)

1. **Recipes.** Replace the per-line `curl` + `jq` loops with one `curl` on the first input (raw JSON, no jq) and the
   `jevx ask ... --lines/--states` table for the batch. Recipes 01, 02, 03, 09, 10 and 11 are the loop ones. The 12
   one-shot recipes only use `| jq -c .answers` as a pretty-printer and can drop it (re-record their output, since the
   raw reply carries `answers`, `model` and `usage`).
2. **Record outputs with `--fresh`.** "Real output" blocks must come from the model, not from the cache.
3. **Give every model build a distinct `model` name.** The cache key contains the profile's `model` string. If a
   retrained or re-quantised openjevx keeps answering as `openjevx`, users keep getting the previous build's answers for
   up to 7 days. Report the build in the reply's `model` field and the recipes' profile, e.g. `openjevx-0.5.0`, or tell
   users to run `jevx cache clear` after upgrading the model. (jevx keys on the configured profile model, so the profile
   line in the recipes/README is where the version belongs.)
4. **Pin the minimum jevx.** State "jevx v0.11.0 or newer" wherever a recipe shows the table or `--fresh`.

## Consequences

- Recipes read as plain commands and plain tables; `jq` becomes optional for `--raw` users.
- Repeat calls against the local model return in about 7 ms instead of about 350 ms.
- Stale-answer risk after a model swap is real and is handled by decision 3.
