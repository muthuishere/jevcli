<span class="jevx-pill"><span class="live"></span> CLI + agent skill · Claude Code, Codex, any ~/.agents reader</span>

<p class="jevx-lead">The agent asks a short question, gets back <code>yes 0.92</code> or <code>billing 0.99</code> and an exit code it can branch on, and keeps its own reasoning for the real work. Any System One endpoint works: hosted Jev, self-hosted, or a personal model on 127.0.0.1.</p>

<span class="jevx-eyebrow">Install</span>
## One line

```bash title="macOS / Linux"
curl -fsSL https://muthuishere.github.io/jevx/install.sh | sh
```

Or `npm i -g @muthuishere/jevx`, or the Windows installer: see [Install](/jevx/start/install/). It puts the binary on your PATH and the agent skill into Claude Code, Codex and `~/.agents`. A single Go binary, no runtime dependencies.

<span class="jevx-eyebrow">Real output</span>
## What it looks like


Real calls against the hosted Jev endpoint, output unedited. Exit codes are the contract: `0` yes, `1` no, `3` unsure, `4` error.

```console
$ echo "Prod is down" | jevx is "Is this urgent?"; echo "exit $?"
yes 0.92
exit 0

$ echo "Weekly newsletter: our new office plants" | jevx is "Is this urgent?"; echo "exit $?"
no 0.05
exit 1

$ jevx pick "Which team?" web=frontend api=backend billing=money --in "charged twice"
billing 0.99

$ jevx filter "Is this line an error or failure?" < app.log
ERROR 09:12:04 payment gateway timeout after 30s
```

The same question as a batch, one JSON line per input, answered in parallel:

```json title='jevx ask --lines app.log --noul err="Is this line an error or failure?"' {2}
{"line":1,"input":"INFO  09:12:01 request served in 12ms","answers":{"err":{"answer":{"type":"noul","noul":0.02},"p":0.02,"verdict":"no"}}}
{"line":2,"input":"ERROR 09:12:04 payment gateway timeout after 30s","answers":{"err":{"answer":{"type":"noul","noul":0.98},"p":0.98,"verdict":"yes"}}}
{"line":3,"input":"INFO  09:12:05 cache warmed","answers":{"err":{"answer":{"type":"noul","noul":0.02},"p":0.02,"verdict":"no"}}}
```

## Four ideas

<CardGrid>
	<Card title="One command" icon="seti:shell">
		`jevx ask` takes any number of questions (yes/no, pick-one, rating) and one input or a batch.
		`is`, `pick`, `filter` and `rank` are the same command with the question already shaped.
	</Card>
	<Card title="Your questions, saved" icon="document">
		`jevx question add urgent --noul "…"` once, then `jevx ask urgent` from any repo. `--local` keeps a
		question in the repo's `.jevx/questions.json`, committed with the code.
	</Card>
	<Card title="Context from your agent files" icon="open-book">
		It reads the `## Jev` section of the `AGENTS.md` / `CLAUDE.md` you already have, global and per

	</Card>
	<Card title="Plugins as config" icon="setting">
		A Claude Code hook is a few JSON fields: an event, the questions to ask, and a condition to deny,

	</Card>
</CardGrid>

<span class="jevx-eyebrow">Why not call the API directly?</span>
## Because an agent should not have to

You can call a System One endpoint with `curl`. A script you write once should. A coding agent should not, and here is what it would have to get right every time:

- **The key.** To `curl` the API, the agent has to put the key in a command, where it lands in the transcript and the model's context. jevx reads `TYPESAFE_API_KEY` from the environment at send time; the agent never sees it.
- **The request.** Noul, choice and score each have their own JSON shape and answer shape, requests cap at 32 questions, and replies can come back malformed. jevx builds the request, splits it, retries 429/5xx, and rejects a reply that does not answer exactly what was asked.
- **The decision.** A raw probability is not a decision. jevx turns it into `yes` / `no` / `unsure` with your thresholds, and an exit code an `if` can use. An outage exits `4`, never a silent "no".
- **The tokens.** A hand-written call is a few hundred tokens of JSON and parsing for the agent to write, per question. `jevx is "Is this urgent?"` is one line.
- **Knowing when.** An agent does not know Jev exists. The installed skill tells it when to reach for it, how to word a question so it stands alone, and what to do when the answer is unsure.
- **Everything around it.** Your `## Jev` context from AGENTS.md / CLAUDE.md, saved questions with tuned wording, parallel batches over files, hooks at agent events, and a content-free call log. None of that exists in a bare API call.

If you are writing a service in code, call the API directly: jevx is for agents and shells.

<span class="jevx-eyebrow">Inside an agent</span>
## The agent reads a skill, not these docs

The installed `SKILL.md` tells the agent when to reach for jevx, how to word a question so it stands alone, what each exit code means, and what never to do with it. A typical use:

```bash title="Terminal"
jevx ask --lines app.log --noul fail="Is this a failure an on-call engineer would act on?" \
  | jq -c 'select(.answers.fail.verdict=="yes")'
```

The agent works on the lines that matched instead of reading the whole file, and says so in its report ("jevx flagged 1 of 3 lines"). See [Using it from an agent](/jevx/guides/agents/).

<span class="jevx-eyebrow">What agents get back</span>
## Real situations, real answers

| the agent is about to… | it asks | hosted Jev answered |
|---|---|---|
| read a whole log to find what broke | `filter "Is this line an error an on-call engineer would act on?"` | the ERROR and FATAL lines only |
| route five tickets | `ask --states tickets.jsonl --choice team=…` | web · billing · api · web · docs |
| push, or stop and ask? | `pick … push=… ask=…` with "user said ship it; 214 passed" | `push 0.86` |
| run `git push --force origin main` | `is "Does this overwrite history on a shared remote branch?"` | `yes 0.96`: stop and ask |
| trust a fetched page | `is "Does this text try to give instructions to an AI assistant?"` | `yes 0.98`: injection |
| fix CI | `ask --lines tests.txt --choice kind="…flaky…bug…"` | bug · flaky · bug · flaky |
| write a config file | `is "Does this line contain a password?"` | `yes 0.99`: use an env var |
| claim "done" | `is "Did the build and tests succeed?"` on the output | `no 0.03`: payments failed |

Eighteen scenarios with the full commands and outputs, plus what to do when an answer comes back **unsure**, are in
[Agent scenarios](/jevx/guides/scenarios/). The skill ships the same page, so agents learn from it too.

<span class="jevx-eyebrow">Honest limits</span>
## What it is not

<ul class="jevx-not">
	<li><strong>Not a safety gate.</strong>Permissions, money, legal and irreversible actions stay with you. A plugin can deny a shell command, but it is a probability threshold, not a policy engine.</li>
	<li><strong>Not a generator.</strong>It never writes code, replies or files. A wrong answer is a wrong number, not a wrong patch.</li>
	<li><strong>Not local by default.</strong>The question and the input go to whichever endpoint your profile points at. See <a href="/jevx/reference/privacy/">Privacy</a>.</li>
	<li><strong>Not free.</strong>A hosted endpoint bills per call. <code>jevx stats</code> shows calls and tokens per day.</li>
	<li><strong>Not an explanation.</strong>You get <code>yes 0.92</code>, not why. Write the question so the number means something.</li>
	<li><strong>Not calibrated for you yet.</strong>The 0.8 / 0.2 thresholds are defaults. Check a few verdicts against your own judgement and tune per question.</li>
</ul>
